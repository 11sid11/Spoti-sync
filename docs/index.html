UPDATE AN EXISTING INSTALLATION

Keep the installation. Replace only the code.

Spoti Sync checks GitHub release metadata automatically but never silently replaces executable code. Update the same bound Apps Script project so your Spotify connection, jobs, playlist IDs, Activity history, and scheduler state remain local.

Download latest

  1. Open your existing Sheet → Extensions → Apps Script.
  2. Replace all contents of Code.gs with the latest bundle and Save.
  3. Reload the same Sheet.
  4. Choose Spoti Sync → Open Spoti Sync once. The local data migration runs automatically.

Spoti Sync 1.4 keeps your Client ID, OAuth tokens, Job IDs, source/target playlist IDs, custom intervals, Activity history, heartbeat phrase state, and compatible scheduler trigger. You do not need to reconnect Spotify or recreate jobs.

Updates are intentionally not installed silently. You explicitly replace the code so repository changes cannot silently rewrite Apps Script in your Google account.

SYNC BEHAVIOR

Few concepts, predictable behavior.

Exact Mirror
Missing source tracks are added and obsolete managed target tracks are removed.
Append Only
Missing source tracks are appended. Existing target tracks are never removed.
Automation
Off, Daily, or Every N days. One daily Apps Script trigger evaluates every automated job; longer intervals do not create extra triggers.
Playlist status
Optional per job. A successful sync can refresh the target description with Spoti Sync wording, sid.is-a.dev, and the completion time. Playlist names are never changed.
Google Sheet
The visible Sheet is status and Activity output. Job configuration stays in the Spoti Sync sidebar.

PRIVACY & SECURITY

No central credential store.

OAuth + PKCE

No Spotify client secret is required. Refresh/access tokens stay in Apps Script User Properties.

Liked Songs stays read-only

Spoti Sync intentionally does not request Spotify's library-modification scope, so it cannot unlike tracks.

Explicit targets only

Playlist-item and optional description writes are limited to playlist IDs configured as job targets.

Local operational data

Job records, status and Activity remain in the user's own bound Sheet or Apps Script properties.

Explicit updates

Version checks never silently replace Apps Script code. Users explicitly install repository updates.

TROUBLESHOOTING

Common setup issues.

The Spoti Sync menu did not appear

Make sure the bundle was saved in the Apps Script project bound to the same Sheet, then reload the spreadsheet tab.

Spotify says the redirect URI is invalid

Use the exact Redirect URI shown after choosing Spoti Sync → Open Spoti Sync.

A playlist returns HTTP 403

Use a target playlist the authorized Spotify account can modify. Description updates additionally require ownership; if only that optional update is rejected, the music sync records a warning.

Where did Jobs and Schedule go?

Spoti Sync 1.4 intentionally makes the sidebar the only normal configuration surface. Jobs is hidden local persistence and a legacy Schedule sheet is preserved hidden. Use the visible Spoti Sync and Activity sheets for status/history.

Why didn't Spoti Sync change my playlist description?

Edit the job and make sure Show Spoti Sync status in playlist description is enabled. Turning it off deliberately skips description updates without blanking the current description.

Can I share one installation between multiple Spotify accounts?

Use a separate Sheet/Apps Script copy for each primary Google + Spotify account so OAuth state and automation remain unambiguous.
