Make Spotify playlists follow your Liked Songs.

The GitHub Pages site never receives your Spotify token, Client ID, playlist contents, or Google authorization. Treat one Sheet/Apps Script installation as belonging to one primary Google + Spotify account; use a separate copy for another account.

UPDATE AN EXISTING INSTALLATION

Keep the Sheet. Replace only the code.

Spoti Sync 1.2+ checks GitHub for release metadata automatically. When an update is available, use this section to replace the Apps Script bundle in your existing installation. Your jobs, history, Spotify Client ID, OAuth tokens, and scheduler stay with the same Sheet/script project.

Download latest

  1. Open your existing Sheet → Extensions → Apps Script.
  2. Replace all contents of Code.gs with the latest bundle and Save.
  3. Reload the same Sheet.
  4. Run Spoti Sync → Initialize / Repair Sheets once.

Updates are intentionally not installed silently. The running script checks only a small version metadata file from GitHub. You explicitly replace the code, so a repository change cannot silently rewrite the Apps Script running in your Google account.

GUIDED SETUP

Install in a few deliberate steps.

Nothing runs on your laptop after setup. The only code you install is the single generated Apps Script bundle from this repository.

Your setup progress0 of 7 complete

  1. Create a blank Google Sheet

    This Sheet will become your Spoti Sync installation and hold non-sensitive job configuration/history.

    Create blank Sheet

  2. Open Apps Script

    In the Sheet, choose Extensions → Apps Script. Delete the default contents of Code.gs.

  3. Paste the Spoti Sync bundle

    Copy the generated bundle below, paste it into Code.gs, and press Save. The install file is generated from the modular source in this repository.

    Download file

  4. Reload the Sheet and open Setup

    Reload the spreadsheet. A Spoti Sync menu appears. Choose Spoti Sync → Setup. Google will ask you to authorize the script when a protected service is first used; review the requested permissions and continue.

  5. Create your Spotify Developer app

    The Setup sidebar shows your installation's unique Redirect URI. Create a Spotify app, add that exact Redirect URI, select Web API, and copy its Client ID.

    Open Spotify Developer Dashboard

    Spotify Development Mode currently requires the app owner to have Spotify Premium. Each Spoti Sync installation uses its own app instead of sharing a central Client ID.

  6. Connect Spotify and add jobs

    Paste the Client ID into the Setup sidebar and authorize Spotify. Then use Spoti Sync → Add Sync Job.

    Append-only archiveLIKED_SONGS → APPEND → targetInterval: 10 days

  7. Preview, sync, then enable automation

    Run Preview Enabled Jobs first. It reads Spotify but does not modify playlists. If the additions/removals look right, run Sync Now, then enable the daily scheduler from Setup.

SYNC BEHAVIOR

Predictable by design.

MIRROR
Target Spotify tracks have the same membership as the source. Missing tracks are added; obsolete tracks are removed. Unsupported local files/episodes are left alone.
APPEND
Only missing source tracks are appended. Nothing already in the target is removed. For Liked Songs, missing tracks append oldest-to-newest.
One scheduler
A single daily trigger checks all jobs. A 10-day job does not create a second Google trigger; it simply runs when due.
Update checks
The same daily scheduler checks a small GitHub version metadata file at most once per day. It never silently replaces or executes code from GitHub.

PRIVACY & SECURITY

No central credential store.

OAuth + PKCE

No Spotify client secret is required. Your refresh/access tokens stay in Apps Script User Properties.

Liked Songs stays read-only

Spoti Sync intentionally does not request Spotify's library-modification scope, so it cannot unlike tracks.

Explicit targets only

Writes are limited to playlist IDs that you put in the Jobs sheet.

Inspectable history

Job configuration and bounded run history are visible in your own spreadsheet.

One account per install

Use one Sheet/Apps Script copy per primary Google + Spotify account. Separate installs keep User Properties, triggers, and playlist configuration unambiguous.

TROUBLESHOOTING

Common setup issues.

The Spoti Sync menu did not appear

Make sure the bundle was saved in the Apps Script project bound to the same Sheet, then reload the spreadsheet tab. The menu is created by the bound script's onOpen() trigger.

Spotify says the redirect URI is invalid

Use the exact Redirect URI shown in Spoti Sync → Setup. Copy it without changing case, slashes, or characters, then add it to the Spotify app's allowlist.

A playlist returns HTTP 403

Spotify's current playlist-items endpoint only exposes playlist contents when the authorized user owns the playlist or is a collaborator. Use a playlist your account can modify.

Scheduled sync stopped after months

Spotify Developer Dashboard refresh tokens currently expire after six months. Reopen Setup and authorize Spotify again. Your jobs remain in the Sheet.

Can I share one Spoti Sync Sheet between multiple Spotify accounts?

Do not use one installation as a multi-account service. Make a separate Sheet/Apps Script copy for each primary Google + Spotify account so each installation owns its own OAuth tokens and scheduler.

I changed the target manually

MIRROR restores managed Spotify-track membership to match the source on the next run. APPEND leaves manual target changes alone and only appends missing source tracks.

Why doesn't Spoti Sync install updates by itself?

Silent self-modification would require broader Google permissions or executing remote code automatically. Spoti Sync instead checks version metadata and asks you to explicitly replace the bundle in your own Apps Script project.
